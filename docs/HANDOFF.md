# HANDOFF: AgroSim BBCH (передача в новий чат)

## Що це
Навчальний симулятор фаз розвитку рослин за шкалою BBCH (українською й англійською) з тренажером визначення фази.
Автор і замовник: Володимир Нікорич (ЧНУ імені Юрія Федьковича). Сімейство продуктів AgroSim (див. сусідній проєкт `agrosim`: якісні реакції та фізичні властивості добрив).

## Стек і структура
React 18 + TypeScript strict + Vite (`base: './'`) + Vitest + ESLint, без Tailwind, без серверної частини. `src/data` (шкали, культури, джерела) · `src/engine` (логіка) · `src/components` · `src/hooks` · `src/i18n` · `tests` · `docs`. Правила: `.cursor/rules/agrosim-bbch.mdc`.

## Статус
- Етап 1 (каркас, дані, Атлас фаз) — ГОТОВО. Шкала зернових (озима пшениця) повна, коди звірено.
- Етап 2 (лінія розвитку) — ГОТОВО: SVG-рослина, розріз стебла, слайдер з автопрогіном і ключовими фазами, сезонна стрічка, перехід Атлас ↔ рослина, збереження фази (деталі й список авторського в `docs/PROGRESS.md`).
- Етап 3 (тренажер «Впізнай фазу») — ГОТОВО на SVG; режим «Фото» реалізовано, але маніфест порожній: чекаємо від замовника список файлів (це остання зміна програми, інструкція в `docs/PHOTOS.md`).
- Етап 4 (польова діагностика) — ГОТОВО на озимій пшениці: віртуальне поле, вибірка, інструменти, правило 50%, розбір (деталі в `docs/PROGRESS.md`).
- Етапи 5–7 — за планом у `docs/PROGRESS.md` (ще 4 культури, щоденник/звіт, збірка).

## Ключові рішення
- Джерело істини: BBCH Monograph (Meier, JKI, 2018, DOI 10.5073/20180906-074619, CC BY 4.0). Текст сторінок PDF не витягується (зображення), тому коди зернових звірено з вторинними джерелами (`cross-checked`).
- Не вигадувати коди, визначення, календарні дати, норми, препарати, DOI/авторів. Українські терміни й розділ «Як визначити в полі» — авторські (`authored`), узгодити з кафедрою.
- Шкала зернових не містить кодів 20, 34–36, 91 (вони є в Zadoks). 19 = «9 і більше листків».
- «Календар» реалізовано як якісну сезонну стрічку без дат (дати залежать від зони, сорту й погоди й потребують джерела).
- Фото: кафедра власних не має; брати лише відкриті ліцензії (CC0, CC BY, CC BY-SA, public domain) з перевіркою на сторінці файлу; маніфест + скрипт завантаження (`docs/PHOTOS.md`); без файлів працює SVG-резерв.
- Етап 2: слайдер індексний (рівні кроки по кодах шкали; 20, 34–36, 91 у зернових пропущено). `seasonOf`, розріз стебла між стадіями й розміри рослини — авторське, підписано в інтерфейсі. Після BBCH 90 модель дає `tillers = 0`, але SVG малює пагони далі (`code >= 30` → 5).
- Етап 2: відстані вузлів у `plantModel` — кумулятивні (1/3/5), шкала дає кроки (1/2/2); в інтерфейсі показувати кроки, суми — лише як похідні.
- Етап 3: питання на SVG чесні: варіанти завжди розрізнювані на малюнку (`observableKey`), розріз стебла показується лише коли відрізняє варіанти, до відповіді в DOM немає коду фази (ні в `aria-label`, ні в `alt`, ні в імені файлу). Це покрито тестами; не послаблювати.
- Етап 3: політика ліцензій живе в одному місці — `src/engine/photoRules.mjs` (його імпортують і застосунок, і `scripts/fetch-photos.mjs`). Пари «часто плутають» — авторські (згенеровані за сусідством кодів).
- Правило фази поля (етап 4): стадія поля — найвища стадія, якої досягли щонайменше 50% рослин (`ref-bbch-2001`, загальна частина 2-го видання; береться головне стебло). Інших порогів немає: «початок/повна фаза» і розмір вибірки в джерелі відсутні, тому розмір вибірки обирає студент, а розкид стадій у віртуальному полі — авторський параметр. Коди порівнюються за числовим порядком шкали (монографія формально допускає порівняння лише в межах однієї головної стадії; для віртуального поля це умовність).
- Етап 4: інструменти поля (`engine/field.ts`, `TOOL_GROUPS`) — лише з тексту шкали зернових: 30–33 потребують розтину з лінійкою, 85/87/89/92 — перевірки нігтем. Для невизначених показань малюнок рослини показує нижню стадію діапазону, щоб не видати відповідь; не змінювати.

## Технічні нотатки середовища
- Мережа для bash у sandbox вимкнена: `npm install` і завантаження фото неможливі. Перевірка: esbuild із `/opt/npm-tools/node_modules` (NODE_PATH; тести збираються з `--alias:vitest=<shim>` і `--alias:lucide-react=<заглушка>`), мінімальний shim для Vitest (чекає на `async`-тести й має `rejects.toThrow`), заглушки типів для `tsc` (`react`, `react-dom`, `lucide-react`, `vitest`; `@types/react` у sandbox немає), Playwright/Chromium для скриншотів і наскрізних сценаріїв (`file://` + зібраний `main.tsx`). ESLint у sandbox немає.
- `sh` не підтримує `mkdir -p {a,b}` — створювати каталоги циклом.
- Після змін: `npm run check` (tsc + eslint + vitest + build) — у sandbox повністю не запускалось (див. «Перевірки етапу 2» у `docs/PROGRESS.md`), запустити в Cursor першим.
- Не забувати `present_files` для архіву.
- `vite.config.ts`: `include: ['tests/**/*.test.{ts,tsx}']`; тести компонентів — `.test.tsx` (`renderToStaticMarkup`, середовище `node`). `tsconfig`: `resolveJsonModule` для `photos.manifest.json`.
- Скрипт `scripts/fetch-photos.mjs` приймає підставні `fetchImpl` і `fs`: тестується без мережі й без `@types/node`.
