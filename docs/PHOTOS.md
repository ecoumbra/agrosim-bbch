# Фото з відкритих джерел

Кафедра власних фото не має, тому тренажер використовує фото з відкритих джерел (насамперед Wikimedia Commons).
Без фото тренажер повністю працює на схематичних SVG-малюнках; режим «Фото» з'являється в налаштуваннях тренажера сам, щойно в маніфесті є хоча б одне правильне фото.

## Політика
- Дозволені ліцензії: CC0, CC BY, CC BY-SA, public domain. NC, ND, GFDL і «усі права захищені» не дозволені (їх відхиляє і скрипт, і застосунок: `src/engine/photoRules.mjs`).
- Для кожного фото в `src/data/photos.manifest.json`: `id`, `crop`, `code` (BBCH), `source` (URL сторінки файлу), `author`, `license` (канонічний запис: `CC0`, `CC BY 4.0`, `CC BY-SA 3.0`, `Public domain`), `attribution`, `file`, `checked` (дата перевірки ліцензії), `verifiedBy`.
- Фото додається лише після того, як код BBCH підтверджено експертом (викладачем) або описом у джерелі. Скрипт код не визначає: його вказують у полі `verifiedBy` кандидата (ПІБ експерта або `source`).
- Файл має нейтральне ім'я `p-<хеш>.jpg|png|webp`, а `attribution` не повинен містити «BBCH» чи двозначне число: інакше код фази видно в DevTools або в підписі до відповіді.

## Як додати фото (ваша робота, остання зміна програми)
1. Скопіюйте `scripts/photos.candidates.example.json` у `scripts/photos.candidates.json` і заповніть: `crop` (`winter-wheat`), `code` (код зі шкали), `title` (назва файлу на Commons з префіксом `File:`), `verifiedBy`. Якщо на Commons не вказано автора, додайте поле `author`.
2. Спершу перевірка без завантаження (вкажіть свою пошту або сайт: це вимога Wikimedia до User-Agent):
   `npm run photos -- --dry-run --contact ваша@пошта`
3. Якщо звіт без відхилень, завантаження: `npm run photos -- --contact ваша@пошта`
   Скрипт бере ліцензію й автора з API Commons, качає зображення (ширина до 1200 px) у `public/photos/`, перевіряє тип файлу за вмістом, дописує записи в маніфест (повторний запуск уже додані пропускає; `--refresh` качає наново).
4. `npm run check`: тест `photos.test.ts` перевіряє весь маніфест, тож хибний запис зупинить збірку.
5. Зафіксуйте в репозиторії `public/photos/*` і `src/data/photos.manifest.json`.

## Як це працює в тренажері
- Режим «Фото» ставить питання лише про фази, для яких є фото. Перед початком сесії зображення завантажуються; питання, чиє фото не завантажилось, відкидаються (SVG-запасу немає: він не розрізняє всі фази). Якщо не завантажилось жодне, показується повідомлення.
- Біля фото одразу видно автора й ліцензію (`attribution`); посилання на сторінку файлу з'являється лише після відповіді (в ньому може бути назва файлу). Список авторів фото сесії є в підсумку.

## Що НЕ перевірено
- `scripts/fetch-photos.mjs` ніколи не запускався проти живого API Commons (у середовищі розробки немає мережі). Логіку перевірено на макетах відповідей, складених за структурою API (`tests/fetchPhotos.test.ts`, мітка TEST_FIXTURE), тож перший запуск (бажано з `--dry-run`) підтвердить, що реальні поля (`extmetadata.LicenseShortName`, `Artist`, `descriptionurl`, `thumburl`) збігаються з очікуваними.
- Для CC BY / CC BY-SA біля фото показано автора й назву ліцензії, а текст ліцензії доступний за посиланням на сторінку файлу. Чи достатньо цього для вимог атрибуції у вашому випадку, варто узгодити з кафедрою.
